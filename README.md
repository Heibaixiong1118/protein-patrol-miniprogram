# 蛋白质纠察队 · 健身热量记录微信小程序

面向健身房进阶用户的饮食记录工具：算清每日**热量缺口**与**蛋白质摄入**，配打卡海报裂变与全渠道获客归因，从零独立完成的完整小程序项目。

## 核心功能

| 功能 | 说明 |
|---|---|
| 目标计算 | 按体重与目标（减脂 26 / 维持 32 / 增肌 38 kcal/kg）自动得出每日热量与蛋白质目标 |
| 记一餐 | 云端食物库模糊搜索（16 种内置健身常见食物，每 100g 营养数据），按克数实时计算热量与三大营养素 |
| 记运动 | 内置 6 种常见训练消耗预设（力量训练 / 跑步 / 游泳等） |
| 今日分析 | 热量缺口大数字 + 蛋白质 g/kg 体重达成度 + 三大营养素拆分 + 目标针对性点评 |
| 打卡海报 | Canvas 2D 绘制战绩图，自动贴带渠道参数的小程序码，保存相册分享朋友圈 |
| 近 7 天趋势 | 每日摄入 / 消耗 / 蛋白素三列对比 |
| 演示模式 | 内置 MOCK_MODE 本地模拟数据层，无需云端即可在开发者工具跑通全流程 |

## 增长闭环设计

所有获客入口统一携带 `channel` 参数，新用户首次进入时随静默登录落库，实现零成本渠道归因：

```
渠道触达(带 channel) → 秒开首体验(免登录) → 静默登录建档(渠道归因落库)
→ 订阅消息留存 → 海报/分享裂变 → 新用户回流(闭环)
```

| 渠道 | channel 归因值 |
|---|---|
| 首页 / 分析页分享卡片 | `share_index` / `share_result` |
| 朋友圈链接 | `moments_*` |
| 邀请活动页 | `invite` |
| 打卡海报扫码 | `poster`（wxacode.getUnlimited scene 参数） |

## 本地运行（演示模式，5 分钟）

1. 微信开发者工具「导入项目」，目录选本仓库根目录
2. 直接点「编译」——默认 `MOCK_MODE = true`，数据走本地缓存模拟，无需任何云端配置
3. 体验完整链路：设目标 → 搜食物记一餐 → 记运动 → 今日分析 → 生成海报

## 切换真实云端

1. `utils/cloud.js` 中 `MOCK_MODE` 改为 `false`
2. `app.js` 中替换云开发环境 ID
3. 部署 `cloudfunctions/` 下三个云函数（云端安装依赖）
4. 云数据库建 `users` / `profiles` / `records`（仅创建者可读写）、`foods`（所有用户可读）四个集合
5. 调用一次 `core` 云函数的 `seedFoods` action 导入食物库

## 合规设计

- 核心功能免登录可用，订阅消息 / 相册授权均在用户感知到价值后触发
- 体重作为敏感个人信息，用户隐私保护指引中单独声明用途（见 `隐私保护指引.md`）
- 个人数据仅创建者可读写，无第三方 SDK 共享

## 技术要点备忘

- 新版编译器要求 `wx:if / wx:elif / wx:else` 使用 `<block>` 链式写法，条件链中间不能插入其他节点
- 小程序码使用 `wxacode.getUnlimited`（scene 参数），生成失败自动降级为纯文字海报
- `lazyCodeLoading: requiredComponents` 按需注入，控制启动耗时
- 统一调用层约定 `{ code, data, message }` 返回格式，前端一次封装双端复用
